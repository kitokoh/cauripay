# ADR-003 — Le wallet est créé à l'inscription (niveau BASIC)

- **Statut** : Proposé → **Accepté** (2026-08-14)
- **Décideur** : Responsable projet (à valider par le propriétaire)
- **Issue** : GOURSI-021b (#186)

## Contexte

La spec prévoit un wallet par utilisateur ; la question de son moment de création n'était pas tranchée
(création à l'inscription vs à la première transaction).

## Décision

**Création à l'inscription** : `POST /auth/register` crée `User` + `Wallet` (type CUSTOMER,
`accountNumber` unique, statut ACTIVE, niveau BASIC) + `KycRecord` dans **une seule `$transaction` Prisma**
(bcrypt pour le mot de passe). Conséquence : tout utilisateur inscrit peut immédiatement recevoir de
l'argent et consulter son solde (0).

## Conséquences

- KYC « BASIC » = niveau de départ (limites faibles, cf. `validation-rules`) ; le passage à
  VERIFIED/PREMIUM passe par kyc-service (ADR-001).
- Le wallet n'est jamais créé « à la volée » côté api-core pour un compte inexistant.
- Un doublon de téléphone/accountNumber échoue en 409 avec message clair.

## Alternatives écartées

- Création paresseuse à la première transaction : rend la réception d'argent impossible sans émetteur
  existant, complexifie l'idempotence.
- Wallet en base ledger seulement : fragilise la traçabilité (l'utilisateur « existe » dans Prisma mais pas
  dans le ledger).
